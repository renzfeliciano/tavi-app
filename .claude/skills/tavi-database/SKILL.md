# TAVI database

PostgreSQL 18 on Neon (D1), Drizzle ORM over node-postgres. Proposal §C holds the full model.

## Table conventions

- `id: id()` from `@/db/columns` — UUIDv7 generated by Postgres (`uuidv7()`).
- `...timestamps()` for `created_at` / `updated_at` (timestamptz). Append-only tables (audit) have only `created_at`.
- SQL names: plural, snake_case (`audit_events`, `organization_id`); TS keys camelCase.
- Status/kind columns: `text(..., { enum })` **plus** a `CHECK` constraint. No Postgres enums (cheap migrations).
- Money: `bigint(..., { mode: "number" })` minor units + a `char(3)` currency with `~ '^[A-Z]{3}$'` check.
- Business dates (issue, due, valid-until): `date`, never timestamptz.
- Every tenant-owned table: `organization_id NOT NULL`, `UNIQUE (organization_id, id)`, and **composite FKs** to other tenant tables: `(organization_id, customer_id) → customers (organization_id, id)`. This makes cross-tenant references impossible in the database.
- Name every constraint and index explicitly (`<table>_<what>`), so errors are readable (`cause.constraint`).

## Migrations workflow

1. Change `schema.ts` (register new files in `src/db/schema.ts`).
2. `npm run db:generate -- --name <what>` → review the SQL in `src/db/migrations/`.
3. Triggers, functions or data fixes: `npx drizzle-kit generate --custom --name <what>`, then write the SQL by hand (see `0003_audit_events_append_only.sql`).
4. `npm run test:int` — the harness wipes the **test** branch and applies every migration from scratch.
5. Commit migration + snapshot files together. Never edit an applied migration; add a new one.
6. Apply to dev: `npm run db:migrate` (uses `DATABASE_URL_DIRECT`). Production migrations: see `tavi-ops`.

## Transactions and concurrency

- Business changes run in `db.transaction(async (tx) => …)` and pass `tx` everywhere inside (audit, outbox, numbering).
- Lock what you're about to change: `.for("update")`. Workers claiming jobs: `.for("update", { skipLocked: true })`.
- Counters and limits: one atomic `INSERT … ON CONFLICT DO UPDATE … RETURNING` (see `allocateDocumentNumber`, `consumeRateLimit`). Never read-then-write.
- Document numbers come **only** from `allocateDocumentNumber(tx, orgId, kind)` inside the issuing transaction — gapless, concurrency-safe. Never `count(*) + 1`.

## Queries

- Every repository function takes the organization ID from the request context and filters by it. A foreign ID returns "not found", never "forbidden".
- Use the `sql` template for expressions; `sql.raw` is lint-banned outside `src/db/`.
- Postgres rejects a constant in `ORDER BY` — add conditional order terms only when they apply (see `resolveMembership`).
- Drizzle wraps driver errors: assert on `error.cause.code` (`23503` FK, `23514` check, `23505` unique, `42501` our append-only trigger).

## Environments

| Variable | Branch | Used by |
|---|---|---|
| `DATABASE_URL` | `dev` (pooled) | the app |
| `DATABASE_URL_DIRECT` | `dev` (direct) | `db:migrate`, `db:studio` |
| `TEST_DATABASE_URL` | `test` (direct) | `test:int` and E2E — **wiped every run** |

The harness (`src/db/testing/env.ts`) refuses to run if the test URL points at the app's database. Neon's free tier sleeps: the first connection may drop; the harness retries. Browse data with `npm run db:studio` or Neon's Tables view.

## Testing data code

Integration tests live beside the code as `*.int.test.ts`, use `testDb()`, `resetTables()` in `beforeEach`, `closeTestDb()` in `afterAll`, and fixtures from `@/db/testing` (`createTestUser`, `createTestOrganization`, `listAllAuditEvents`). Test concurrency with `Promise.all` over separate transactions.
